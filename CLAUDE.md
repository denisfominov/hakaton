# CLAUDE.md

Alpha Intelligence — новостная аналитика для бизнес-решений (хакатон, трек «Новостная аналитика», КИБ).
Backend на FastAPI + SQLite, frontend на React + Vite + Tailwind. Подробности — в [README.md](README.md) и [docs/](docs/).

## Запуск

### Backend (Python 3.12, uv)

```bash
cd backend
uv venv --python 3.12
source .venv/bin/activate        # Windows: .venv\Scripts\activate
uv pip install -r requirements.txt
uvicorn app.main:app --port 8000 --reload
```

- При первом запуске создаётся `backend/alpha.db` (профили пяти компаний + подборка новостей).
  Для чистого старта удалить `backend/alpha.db`.
- API-документация: http://127.0.0.1:8000/docs
- Настройки — переменные окружения, пример в [.env.example](.env.example) (скопировать в `.env`).
  Без `.env` всё работает: реальная подборка + анализ на правилах. `DATASET=synthetic` — тестовый набор.
  LLM — только разрешённые кейсом модели (Qwen3.6, GLM-5.3, Gemma 4, DeepSeek-V4.1 и др.) через `LLM_PROVIDER`
  (`gateway` — шлюз организаторов, `local` — своя модель под Ollama/vLLM, `off`). OpenAI/Anthropic API не используем.
  Данные клиентов кейса — `CLIENT_DATA_DIR`, аналитика банка для RAG — `BANK_DOCS_DIR`.

### Frontend (Node.js 20+)

```bash
cd frontend
npm install
npm run dev
```

Открыть http://127.0.0.1:5173. Vite проксирует `/api` на backend (порт 8000).
Проверка сборки и типов: `npm run build`.

### Docker (всё в одном контейнере)

```bash
docker build -t alpha-intelligence .
docker run -p 8000:8000 -v alpha-data:/data --env-file .env alpha-intelligence
```

Открыть http://localhost:8000: FastAPI отдаёт и API, и собранный фронтенд (`FRONTEND_DIST`), база — в томе `/data`.

### Тесты

```bash
cd backend
python -m pytest -q
```

Работают без интернета и без ключей (логика на синтетическом наборе + проверки реальной подборки).
Внешние источники в тестах отключены фикстурой `no_network` (tests/conftest.py) — тест, которому нужен ответ
источника, подменяет его своей фикстурой.

## Рабочий процесс (с версии 8)

Каждый промпт = новая версия проекта. Ветки версий больше не плодим: всё живёт в `main`, работа над задачей —
в короткой ветке фичи, в `main` она попадает через пулл-реквест. Так начинается каждое решение после промпта.

1. **Сел за компьютер или Mac — обновил `main`:**
   ```bash
   git checkout main
   git pull
   ```
   Если тег предыдущей версии ещё не стоит (PR слили в интерфейсе GitHub), поставить его на `main`:
   `git tag vN-1 && git push origin vN-1`.
2. **Новая фича — новая ветка от свежего `main`:**
   ```bash
   git checkout -b feature_name
   ```
   Короткое имя по смыслу задачи латиницей: `docker`, `portfolio-export`, `fix-feed-paging`.
3. **Делаешь задачу и коммитишь логичными шагами.** Прогони тесты (`cd backend && python -m pytest -q`)
   и проверь, что backend и frontend запускаются (`npm run build`).
4. **Документация версии в той же ветке:** в начало README.md — блок «Версия N» (что добавили, что изменили,
   что не работает, как запустить); сверху в CHANGELOG.md — запись (дата, N, изменения относительно N-1).
5. **Пушишь ветку:** `git push -u origin feature_name`.
6. **Из ветки создаёшь пулл-реквест в интерфейсе GitHub** (`main` ← `feature_name`):
   https://github.com/denisfominov/hakaton/compare/main...feature_name?expand=1
   Если `gh` не установлен, дай пользователю эту ссылку.
7. **Мержишь пулл-реквест**, затем `git checkout main && git pull` и тег версии:
   `git tag vN && git push origin vN`. Ветку фичи после слияния можно удалить.
8. Не коммить .venv, node_modules, .env, alpha.db, pycache. Секреты в код и README не писать.
9. В конце ответа напиши, как открыть эту версию: `git checkout main && git pull` (или `git checkout vN`).

### История веток (только для справки, не менять)

v1 — `первый-промпт`, v2 — `второй-промпт`, v4 — `prompt-4-(почка-от-prompt-2)`, v5 — `prompt-5`,
v6 — `prompt-6`, v7 — `prompt-7` (слита в `main`, PR #1). Ветку `третий-промпт-(пока-мертв)` не использовать:
кода в ней нет. Теги `v1`, `v2`, `v4`–`v7` стоят на соответствующих версиях.
