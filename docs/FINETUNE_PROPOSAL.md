# Предложение: дообучение разрешённой модели

**Статус: только предложение, не выполняется.** По решению команды (версия 10) модели не обучаются с нуля, не
дообучаются, и никакие модели или веса вне списка кейса не подключаются; собственный AI-слой — это свои небольшие
ML-модели (не LLM), своя агентная логика поверх разрешённых LLM, роутер моделей и контроль бюджета
(docs/COMPLIANCE.md). Ниже — что можно было бы сделать, если организаторы подтвердят, что дообученный адаптер
разрешённой модели допустим.

Идея: открытые веса разрешённой модели (Qwen3.6 35B A3B или Gemma 4 26B A4B) + LoRA-адаптер, обученный на
датасете из данных кейса, с тем же клиентом шлюза. Данные клиентов не покидают контур.

## Что для этого уже есть

- **Один клиент для любых моделей** — [backend/app/llm_client.py](../backend/app/llm_client.py): протокол
  HTTP Chat Completions, который понимают Ollama, vLLM, llama.cpp server и шлюз организаторов. Переход на свою
  модель — смена переменных окружения, код не меняется:
  ```bash
  LLM_PROVIDER=local
  LLM_BASE_URL=http://localhost:11434/v1   # Ollama; для vLLM — http://<host>:8001/v1
  LLM_MODEL_DEFAULT=qwen3.6:35b-a3b        # имя как у сервера; сверяется со списком разрешённых
  ```
- **Белый список** — имя модели нормализуется («Qwen/Qwen3.6-35B-A3B», «qwen3.6:35b-a3b» → «Qwen3.6 35B A3B»)
  и сверяется со списком кейса; неразрешённая модель не вызывается.
- **Ollama в docker-compose** — профиль `local-llm`: `docker compose --profile local-llm up`.
- **Датасет из данных кейса** — `python -m scripts.build_case_dataset --out data/sft`. Пример = клиент банка из
  данных кейса (сегмент от 15 млрд ₽) × новость периода кейса × аналитика Альфа-Банка (приложение 2):
  - вход — контекст, который собирает агент: факты новости, признаки клиента (ОКВЭД, масштаб, место в отрасли,
    продукты банка, ВЭД, контрагенты по платежам), выводы правил, цитаты аналитики банка со ссылками;
  - выход — ответ в JSON-схеме агента: почему важно, риски, возможности, позиция банка, действия, сценарии,
    ответ на уточняющий вопрос;
  - на клиента — самые значимые для него новости и несколько незначимых (модель должна уметь сказать «не важно»),
    часть примеров — с уточняющими вопросами ЛПР;
  - разбиение без утечек (курс ML): по группе компаний, стратифицированно по классу ОКВЭД, и по времени — в
    train/val только новости до отсечки, в test — новые клиенты и более поздние новости.
  Первая сборка: 115 клиентов, 1037 пар, после отсечки по времени — 539 примеров (train 295, val 64, test 180),
  у 9 из 10 есть позиция банка (`data/sft/dataset_card.json`). Train/val — новости до 13 октября, test — новые
  клиенты и все новости, включая поток RSS 18–19 октября.
  Данные кейса и датасет в git не кладутся.
- **Учитель** — без ключа шлюза целевой ответ дают правила и проверки агента (учат формату, разделению
  «факт / банк / AI» и опоре на источники). С ключом: `--teacher <модель>` — ответ разрешённой модели после
  пост-проверки агента. Модель-учитель выбирается сравнением (`scripts/compare_models.py`, docs/MODEL_COMPARISON.md),
  ожидаемо — GLM-5.3-Flash.
- **Аналитика банка в датасете** — PDF приложения 2 состоят из картинок страниц; текст получен распознаванием
  (`scripts/ocr_bank_docs.py`: встроенный OCR macOS полосами страницы или разрешённая Qwen3-VL), с номерами страниц.
- **Журнал запусков** — `python -m scripts.export_sft` выгружает реальные запуски агента пользователями (в `meta` —
  оценка пользователя): это второй источник примеров и пар для DPO.

## Этапы

### 1. Развернуть базовую модель (1–2 дня)

- Кандидаты: **Qwen3.6 35B A3B** (универсальная, MoE: активно около 3B параметров на токен — быстрый вывод)
  и **Gemma 4 26B A4B** (лёгкие задачи: план агента, классификация). Перед размещением проверить лицензию весов на
  карточке модели.
- Сервер: vLLM (продуктив, батчинг, LoRA-адаптеры на лету) или Ollama (разработка). Квантование 4–8 бит.
- Ориентир по железу (уточнить замером): одна GPU 48 ГБ для 35B MoE в 4 битах с запасом под контекст;
  для разработки — Mac с 64 ГБ памяти или облачная GPU по часам.
- Проверка: тот же агент с `LLM_PROVIDER=local`, сравнение со шлюзом на одном наборе событий.

### 2. Собрать датасет (готово для правил, с учителем — после ключа)

- Основа — данные кейса (см. выше): 115 клиентов сегмента × новости × аналитика банка.
- Порядок: сравнить модели → лучшую взять учителем → `build_case_dataset --teacher` → фильтры → 1–3 тыс. примеров.
- Фильтры: валидный JSON по схеме, факты есть в тексте новости, ссылки на аналитику банка существуют, утверждения
  модели прошли проверку опоры на контекст, нет персональных данных.
- Второй источник — оценки пользователей и правки экспертов банка (`export_sft`): пары «лучше / хуже» для DPO.

### 3. Дообучить (LoRA / QLoRA)

- Задача — не «знания», а навык: отвечать на 6 вопросов по схеме, цитировать только данные из контекста,
  отделять позицию банка от выводов модели, учитывать продукты клиента (кредиты, депозиты, ВЭД).
- LoRA-адаптер поверх базовой разрешённой модели; веса базовой модели не меняются.
- **Вопрос к организаторам:** считается ли дообученный адаптер разрешённой моделью. До ответа — в решении для жюри
  используем базовые модели, а адаптер держим как исследование.

### 4. Оценить

| Метрика | Как считаем |
|---|---|
| Фактическая точность | доля фактов, найденных в тексте новости (`llm.verify`) |
| Опора на банк | доля утверждений «позиция банка» с существующей ссылкой на фрагмент |
| Валидность ответа | доля ответов, прошедших JSON-схему с первого раза |
| Персонализация | совпадение с оценками пользователей «относится / не относится»; разные клиенты — разные выводы |
| Скорость и стоимость | задержка, токены на ответ, нагрузка на GPU |

Эталонный набор: test-часть датасета (клиенты и новости, которых не было в обучении) плюс 50–100 пар
«событие × клиент» с ответами, проверенными экспертом. Метрики и скрипт — те же, что в сравнении моделей
(`scripts/compare_models.py`): точка отсчёта — агент без LLM и базовая разрешённая модель. Новая версия адаптера выходит,
только если не хуже базовой модели по всем метрикам.

### 5. Эксплуатация

- vLLM с адаптером за тем же адресом `LLM_BASE_URL`; переключение и откат — переменной окружения.
- Мониторинг: таблица `llm_calls` (задержки, ошибки, токены), доля ответов, отброшенных пост-проверкой,
  оценки пользователей по неделям.
- Цикл: новые оценки и правки → датасет → адаптер → эталонный набор → выкатка.

## Что не делаем

- Не обучаем модель с нуля и не берём модели вне списка кейса.
- Не отправляем данные клиентов во внешние сервисы для обучения.
- Не храним в датасете тексты платежей и идентификаторы физлиц.
