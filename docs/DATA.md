# Данные

## Компании из базы кейса (по умолчанию)

Источник — обезличенные данные организаторов (приложение 1), папка `CLIENT_DATA_DIR`:

| Файл | Что берём |
|---|---|
| `df_Uid_data_hack.csv` | карточка компании: `SYNTHETIC_U`, ОКВЭД, регион и город, `REVENUE_COMPANY`, численность (градации ФНС/СПАРК), тип клиента, продукты банка (`CL_PRODUCT_*_MARK`), ВЭД (`FTS_FLAG`, `FTS_COUNTRY_NAME`), группа, стадия, возраст |
| `df_Uid_payment_hack.csv` | платежи между компаниями: `PAYER`, `BENEFICIARY`, `PAY_AMT`, `PAY_CNT` — основные поставщики и покупатели |
| `df_Fid_Uid_link_hack.csv` | связи физлиц с компаниями — аффилированные компании (без персональных данных) |

**`REVENUE_COMPANY`** — выручка в рублях (число, не градация) за 2025 год (ответ В14). Пустое или нечисловое значение
считается нулём. Значение 1000 — техническая заглушка организаторов, данных нет; пока считается настоящей выручкой —
исправит A10.
Сегмент КИБ — выручка юрлица **строго больше** 15 млрд ₽ (`clients.SEGMENT_REVENUE`): в данных кейса таких компаний
115, они показываются первыми. Остальные — только через API (`/api/clients?segment=false`): поиск в интерфейсе ищет
только среди 115 (исправлено 2026-10-21, раньше здесь было «доступны поиском»). По ответам В15, В54, В91 сегмент
считается по выручке группы, берутся только действующие клиенты, а анализ — по всей базе: это задача A11. В интерфейсе выручка — в млрд ₽ с одним знаком, плюс место
компании по выручке среди компаний того же класса ОКВЭД.

**Поля по ответам организаторов (вебинар 2026-10-20, docs/QUESTIONS.md):** `GROUP_ID` — юрлица связаны долей
владения, общим бенефициаром или общим единоличным исполнительным органом (В11); `CITY_NAME` — город, где
обслуживается юрлицо, `RC_NAME` — регион (В17); `CL_TYPE`: `CLIENT` — действующий клиент, `CLOSE_CLIENT` — бывший,
`PROSPECT` — потенциальный (В12); `NEGATIVEMARK = 1` — в банке есть достоверные данные о ключевом собственнике (В13);
ФТС — только страна, без направления импорт или экспорт (В18); `PAY_AMT` — рубли, `PAY_CNT` — число операций, период
с 1 января по 31 октября 2026 (В19); платежи самой себе — переводы между своими счетами, исключены (В20);
контрагент без карточки в базе использовать нельзя (В21, исправит A10); тип отношений платёж не показывает —
«поставщик / покупатель» по направлению платежа — наш вывод (В22).

**Подпись компании** (названий в данных нет): `Компания <SYNTHETIC_U>: ОКВЭД <код> <название>, <регион>,
выручка <X> млрд ₽, сотрудников <градация>, продукты банка: <список>` (`clients.label`).

**Демонстрационные клиенты** — пять компаний, по одной на отрасль: в каждой отрасли крупнейший по выручке действующий
клиент банка с продуктами (`clients.demo_client_ids`, детерминированно; переопределяется `DEMO_CLIENTS=U_1,U_2`).
Профили создаются при старте с постоянными id `case-<uid>` (например, `case-u-9250`) — одинаковыми у всей команды,
поэтому работают ссылки входа и кэш ответов модели. На 2026-10-20 это `U_57706` (оптовая торговля топливом),
`U_9250` (инженерное строительство), `U_200890` (оптовая торговля металлами), `U_234228` (оптовая торговля),
`U_102920` (оптовая торговля продуктами).

Ручной ввод новой компании не обязателен (ответ организаторов), но остаётся как дополнительная возможность:
«Компании» → «Добавить компанию вручную по ИНН или сайту». Сервис заполняет профиль сам (ЕГРЮЛ, сайт, открытые
карточки), пользователь правит его и подтверждает.

Нет файлов кейса — вместо них синтетический пример `backend/data/clients/sample` в том же формате.

## Как обновить подборку

1. Найти публикацию, открыть оригинал, выписать факты своими словами (без копирования абзацев).
2. Добавить объект в `backend/data/real/news.json`: `id`, `title`, `summary`, `body`, `source`, `url`,
   `published_at` (ISO с часовым поясом), `reliability`, при необходимости `official`, `time_approx`, `lang`,
   `title_original`.
3. Перезапустить backend или нажать «Обновить ленту → Перезагрузить подборку».
4. `python -m pytest tests/test_real_dataset.py` — проверит ссылки, даты и уникальность.

  не размечаются.
- Обновить оба файла: `cd backend && python -m scripts.build_market_data` (нужен интернет).
- Свой архив старых новостей (выгрузка с Kaggle, медиамониторинг, CSV с колонками `title`, `date`, `text`, `url`):
  `python -m scripts.import_history archive.csv --name <имя>` — новости, где упомянуты компании или темы публичных
  компаний из профилей, попадут в `data/history/<имя>.json` и будут размечены по реакции рынка.

## Синтетический набор (backend/data/synthetic)

Три вымышленные компании и 22 вымышленных события — на них написаны тесты бизнес-логики, потому что для
синтетики заранее известен «правильный» вывод. Включается `DATASET=synthetic`. В интерфейсе такие события
помечены «Демо», ссылок у них нет.
