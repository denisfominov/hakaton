# Аудит: требования кейса «Альфа Хак: Новостная аналитика» → реализация

Состояние на версию 9. Статусы: ✅ сделано, 🟡 частично, ❌ нет. Номера слайдов — по PDF кейса.

## Постановка задачи (слайд 6)

| Требование | Статус | Где в коде | Чего не хватает |
|---|---|---|---|
| 1. Анализ данных о компании и группе: отрасль, виды деятельности, масштаб, положение | 🟡 | `clients.py`: ОКВЭД, выручка, сегмент ≥ 15 млрд ₽, продукты банка, ВЭД (страны ФТС), группа компаний, контрагенты по платежам, связи через физлиц | доля рынка и положение в отрасли не считаются (можно ранжировать по выручке внутри ОКВЭД в наборе) |
| 2. Персонализированный отбор и ранжирование новостей | ✅ | `matching.py`, `analysis.py`, `scoring.py`, `model.py`: профиль × новость → каналы влияния → баллы 0–100, поправка своей моделью | — |
| 3. Персонализированная интерпретация с учётом контекста и аналитики банка | ✅ | `agent.py`: ответ на 6 вопросов; продукты банка меняют вывод (кредиты → долговая нагрузка, депозиты → доходность, ВЭД → валюта) | позиция банка появится, когда материалы приложения 2 будут в `BANK_DOCS_DIR` |
| 4. Пользовательский сценарий в стиле интернет-банка | 🟡 | веб-интерфейс: выбор клиента → обзор/лента → событие → «Инсайт для руководителя» | это отдельное приложение, а не встраивание в Альфа-Бизнес |
| 5. Парсер новостей и материалов банка, классификация, ключевая информация | 🟡 | `sources.py` (RSS, подборка), `nlp.py` (категории, сигналы, сущности), `bank_rag.py` (PDF → фрагменты со страницами) | материалы банка не классифицируются по темам, только ищутся |

## Агентная логика (слайд 7)

| Требование | Статус | Где |
|---|---|---|
| Планирование: какие данные нужны, последовательность шагов | ✅ | `agent.llm_plan` (разрешённая модель выбирает инструменты из реестра) и `agent.heuristic_plan` (без LLM) |
| Работа с инструментами: профиль, новости, аналитика банка, RAG | ✅ | реестр `agent.TOOLS`: 7 инструментов; вызов только из реестра, аргументы проверяются по типам |
| Контекст: результаты шагов используются дальше | ✅ | `agent.Ctx`: данные и источники накапливаются, ответ собирается из них |
| Самопроверка и адаптация | ✅ | `agent.self_check`: факты, связь с компанией, позиция банка, подтверждения; повторный поиск, до 2 раундов |
| Своя реализация, без готовых агентных фреймворков | ✅ | цикл написан на Python, без LangChain, AutoGen и т.п. |

## Формат ответа (слайды 13–14)

| Вопрос | Статус | Тип утверждений |
|---|---|---|
| Что произошло? | ✅ | `fact` — предложения из текста новости с цифрами, ссылки на издания события |
| Почему это важно для этой компании? | ✅ | `client` — элементы профиля и данные банка о клиенте |
| Какие последствия возможны? | ✅ | `ai` — риски и возможности по каналам влияния, горизонт |
| Какие действия могут быть релевантны? | ✅ | `ai` — действие, почему, если сделать, если не реагировать, ответственный, срок |
| Как это оценивает банк? | 🟡 | `bank` — только найденные фрагменты аналитики со ссылкой на файл и страницу; нет материалов — так и пишется |
| На чём основан вывод? | ✅ | список источников с номерами, признаки компании, реакция рынка, ограничения |
| Разделение «факты / банк / AI» и JSON по схеме | ✅ | поле `kind` у каждого утверждения, ответ — JSON |
