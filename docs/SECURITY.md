# Безопасность и данные

Состояние на 2026-10-20. Прототип; что сделано и что нужно для продукта — раздельно.

## Связь пользователя с бизнесом

**В продукте её подтверждает банк, а не сервис.** Пользователь входит в Альфа-Бизнес (аутентификация банка, 2FA),
и банк знает, к каким компаниям у него есть доступ и с какими правами. При нажатии на точку входа банк выпускает
короткий токен: псевдоним пользователя (`sub`), компания (`client_id`), роль, срок 2–5 минут, одноразовый `jti`,
асимметричная подпись. Сервис проверяет подпись, срок, одноразовость и роль и открывает только эту компанию.
Регистрации и своих паролей в сервисе нет (ответ организаторов). Поток — в [ALFA_BUSINESS_ENTRY.md](ALFA_BUSINESS_ENTRY.md).

**В прототипе смоделировано:** токен выпускает сам сервис (`/api/entry/mock-token`, подпись HMAC секретом
`ENTRY_SECRET`) по выбору на макете главного экрана. Проверка (`app/entry.py`) настоящая: подпись, издатель, срок
5 минут, роль из списка, компания есть в данных кейса, повторное использование `jti` отклоняется; каждая попытка
пишется в `entry_log`. **Ограничение прототипа:** компанию можно открыть и без токена — со страницы выбора компании;
сессии после входа нет, роль меняет акценты ответа, но не права доступа.

## Какие данные о бизнесе используем и храним

| Что | Откуда | Где хранится |
|---|---|---|
| Карточка компании: ОКВЭД, регион, выручка, численность (градация), тип клиента, продукты банка, ВЭД, группа, стадия, возраст | `df_Uid_data_hack.csv` (приложение 1, обезличено: `SYNTHETIC_U`) | читается из `CLIENT_DATA_DIR`; в базе — профиль компании, собранный из этих полей |
| Основные контрагенты (обезличенные id, суммы, число платежей) | `df_Uid_payment_hack.csv` | считается на лету, в базу не пишется |
| Аффилированные компании | `df_Fid_Uid_link_hack.csv` (физлица обезличены) | считается на лету; показывается только число общих физлиц, их идентификаторы не показываются и не хранятся |
| Аналитика банка | PDF приложения 2 | индекс в памяти, файлы — только из `BANK_DOCS_DIR` |

**Только поля приложения 1** — других сведений о бизнесе сервис о компаниях кейса не запрашивает и не хранит.
Поиск по ИНН (ЕГРЮЛ, DaData) и сайту компании — только для ручного добавления новой компании (спрятано, по действию
пользователя, публичные источники, robots.txt, внутренние сети запрещены).

**Действия пользователя** — единственное, что сервис хранит сверх этого: оценки релевантности (`feedback`),
избранное, план действий и его история (`actions`, `action_history`), запуски агента (`agent_runs`: вход и ответ
модели — для разбора качества), журнал входов (`entry_log`: `jti`, псевдоним, компания, роль, успех, причина).
Персональных данных нет: имени, телефона, почты пользователя сервис не получает.

Данные кейса, PDF банка, веса своих моделей и выгрузки для дообучения не коммитятся (`.gitignore`) и не попадают
в Docker-образ (`.dockerignore`, проверено в собранном образе 2026-10-20).

## Языковые модели

- Только шесть моделей кейса: белый список в `llm_client.py`, другая модель отклоняется до запроса (тест).
- Перед отправкой в шлюз маскируются контакты и реквизиты (`llm_client.redact`): телефоны, почта, ИНН/ОГРН, счета.
- Текст новостей и документов передаётся модели как недоверенный — в отдельных тегах, без угловых скобок
  (`agent.untrusted`); строки-инъекции («игнорируй инструкции…») вырезаются, подозрительные новости помечаются
  (`nlp.py`); ответ модели проверяется по JSON-схеме, утверждение без источника отбрасывается.
- Ключ шлюза — только из окружения, в журнал, ответы API и исключения не попадает (тест `test_key_never_leaks`).
- Дневной бюджет (по Москве), журнал вызовов без текстов промптов.

## Секреты и конфигурация

`LLM_API_KEY`, `ENTRY_SECRET`, `DADATA_API_KEY`, `ALFA_NEWS_API_TOKEN` — только переменные окружения; `.env`
не коммитится, пример — `.env.example` без значений. `/api/health` предупреждает, если `ENTRY_SECRET` не задан.
CORS — список `CORS_ORIGINS`. Контейнер работает не от root (uid 10001).

## Что нужно для продукта (не сделано)

1. Токен от банка с асимметричной подписью (ES256, JWKS), `aud`, передача не в адресной строке, сессия в
   httpOnly-cookie, ротация ключей.
2. Права по роли на сервере: компания — только из сессии; что видит бухгалтер и что — собственник.
3. Ограничение частоты запросов, особенно к агенту (бюджет LLM общий).
4. Журнал входов и действий — в систему аудита банка; срок хранения.
5. Шифрование базы на диске и резервные копии (сейчас SQLite в томе).
