## Как запустить

```bash
cd backend
python -m scripts.build_case_dataset --out data/sft          # пары «клиент × новость» из данных кейса
python -m scripts.compare_models --pairs 20                   # все текстовые модели из списка кейса
python -m scripts.compare_models --pairs 40 --models "GLM-5.3-Flash,Qwen3.6 35B A3B"
```

## Что сравниваем

Набор — отложенная часть датасета (`test.jsonl`): клиенты кейса, которых не было в обучении, и более поздние
новости; в набор входят значимые новости, незначимые (модель должна сказать «не важно») и уточняющие вопросы.
Каждая модель работает в агенте и как планировщик, и как автор ответа. Точка отсчёта — агент без LLM.

| Метрика | Как считается |
|---|---|
| Успешность | план и ответ модели получены и разобраны как JSON |
| Обоснованность | 1 − доля утверждений модели, отброшенных проверкой (нет опоры на входные данные, нет ссылки на фрагмент банка) |
| Цитат банка | сколько цитат аналитики банка со ссылкой на фрагмент осталось в ответе |
| План валиден | доля шагов плана с инструментами из реестра |
| Ответ на вопрос | модель ответила на уточняющий вопрос |
| Задержка, токены | цена ответа в рамках дневного лимита шлюза |

Итоговый балл = успешность × обоснованность: для ЛПР ошибка «выдумал» дороже, чем «ответил короче». При равном
балле — больше цитат банка, затем меньше задержка. Рядом в отчёте — ответы моделей на одну и ту же пару для
ручной проверки.

## Гипотеза

По назначению моделей в приложении 3 кейса лучшей для ответа агента ожидается **GLM-5.3-Flash** («задачи повышенной
сложности, анализ и рассуждения») — она уже стоит по умолчанию в `LLM_MODEL_REASONING`. Для плана агента — быстрая
Gemma 4 26B A4B (`LLM_MODEL_FAST`). Победитель сравнения станет и учителем для датасета своей LLM
(`build_case_dataset --teacher <модель>`).
