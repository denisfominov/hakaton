# Разнообразие верха ленты (A3) — замер, правила в сервис не включены

Задача A3: топ-10 разных клиентов не должен совпадать (цель — мера Жаккара < 0,4: доля общих новостей среди всех
разных новостей двух топов) без потери точности P@10 (доля значимых новостей в топ-10).

## Как мерили

`backend/scripts/eval_feed_diversity.py`, правила — `backend/app/diversity.py`. Порядок работы — по лекциям 4, 5 и 7
курса ML:

- **Деление по компаниям.** dev — 25 компаний основного набора черновой разметки, 10 отраслей. test — 5 демо-клиентов:
  у них размечены все новости. Набор правил выбирали только на dev, test смотрели один раз.
- **Точка отсчёта.** Текущая лента без правил, условия сравнения одинаковые.
- **Правило выбора, заданное заранее:** меньше всего совпадений при условии, что P@10 не падает.
- **Разброс.** Бутстрэп по компаниям, 95% интервал разницы P@10 с текущей лентой.
- **Метки.** Черновик моделей (docs/a/LLM_DRAFT_LABELS.md), не эталон; «значимо» — важность 2–3. Новость без метки
  считается незначимой, поэтому рядом показана точность только среди размеченных.

Проверяли три правила, их параметры заданы задачей и по разметке не подбирались:

- **macro** — в топ-10 не больше 3 общих макро-новостей (ставка или курс без связи с компанией и её отраслью);
- **story** — в топ-10 не больше одной новости из одного сюжета;
- **nolink** — новость без связи с профилем (совпал только регион «вся Россия») в топ-10 не поднимается.

## Итог

| Вариант | dev: P@10 (разница, 95%) | dev: совпадение топов, все пары / разные отрасли | test: P@10 (разница) | test: совпадение, все / разные отрасли |
|---|---|---|---|---|
| сейчас | 0,388 | **0,315 / 0,274** | 0,540 | 0,481 / 0,401 |
| macro | −0,016 [−0,032; −0,004] | 0,304 / 0,261 | −0,040 | 0,435 / 0,335 |
| nolink | 0 | 0,318 / 0,275 | 0 | 0,522 / 0,417 |
| macro + nolink | −0,008 [−0,020; 0] | 0,309 / 0,267 | −0,040 | 0,436 / 0,337 |
| macro + story | −0,156 [−0,188; −0,124] | 0,264 / 0,218 | −0,140 | 0,346 / 0,227 |

- **Цель по совпадению уже выполнена без правил** на широком наборе: 0,315 у 25 компаний 10 отраслей.
- **Любое правило снижает точность.** Новости о ставке и курсе черновик считает значимыми для большинства компаний.
  Если считать только по размеченным новостям, итог тот же: у macro точность 0,475 → 0,453 на dev.
- **По заданному правилу выбран вариант «сейчас»:** порядок ленты не меняем.
- **Высокое совпадение у демо-клиентов (0,48) — из-за их подбора.** Три из пяти — металлурги, между ними совпадение
  0,67. У пар разных отраслей — 0,40.

## Что дальше

- **D1.** Взять демо-клиентов из разных отраслей под три сценария кейса: кредиты и ставка, ВЭД и курс, отраслевой
  риск. Это убирает одинаковый верх в показе без потери точности.
- **A2.** Перепроверить правила на разметке людей: черновик моделей может переоценивать значимость макро-новостей.
  Скрипт и правила готовы, команда та же.
- **B3.** Добавить отраслевые источники: в ленте мало отраслевых новостей, поэтому макро-новости и оказываются наверху.

## Повторить

```bash
cd backend
python -m scripts.eval_feed_diversity --part dev     # ~3 минуты: признаки компаний по данным кейса
python -m scripts.eval_feed_diversity --part test
```

Нужны данные кейса и черновая разметка `backend/data/overnight/d/llm_draft_labels.csv`; они не в git. База
копируется во временную папку, оригинал не меняется.
