# Черновая разметка пар «компания × новость» моделями — LLM draft, not gold

Прогон 2026-10-20/21, `backend/scripts/overnight_labels.py` (скрипт удалён 2026-10-21 вместе со своей ML-моделью,
C20.2; разметка осталась для замера качества), потрачено **148,9 ₽**. Это **черновик**: эталон (gold) —
только после проверки человеком. **На этих метках модели не обучаем.**

## Что сделано

- **Пары:**
  - основной набор — 30 компаний кейса × 100 новостей = **3000 пар**. Компании: 5 демо-клиентов и 25 других, по
    одной на отрасль по кругу. Новости: 30% — верх по нашей модели, 70% — случайные;
  - расширение — 5 демо-клиентов × **все** 553 новости набора: ещё **2265 пар**. Это полный список новостей для
    P@10 и nDCG@10 по демо-клиентам (задача A2);
  - новости: подборка, живые RSS и история решений по ставке.
- **Метки** (как в A1, docs/TASKS.md): важность 0–3, риск / возможность / нейтрально, срочность.
- **Кто размечал:** GLM-5.3-Flash и DeepSeek-V4.1-Flash — каждую пару независимо, по 10 новостей одной компании за
  вызов. Qwen3.6 решала расхождения: разное «значимо / не значимо», разница важности на 2 и больше, разное влияние
  при важности от 2.
- **Что уходило в модели:** только агрегированные признаки компании — отрасль, диапазон выручки, продукты банка,
  страны ВЭД, регион, отрасли поставщиков и покупателей. Ни строк таблиц кейса, ни идентификаторов.

Не размечены 30 пар (3 вызова вернули не JSON). Как получен итог:
- 3380 пар — модели согласны;
- 1478 — близки, взята меньшая оценка;
- 376 — решила Qwen3.6.

Итоговая важность: 0 — 3102 пары, 1 — 1519, 2 — 562, 3 — 51. У каждого демо-клиента 51–75 значимых новостей из
примерно 550.

**Первый сигнал для A2 (не эталон):** среди 30% новостей, которые наша модель ставит наверх, значимых по черновику
26,2%, среди случайных — 7,8%. Отбор работает лучше случайного в 3,4 раза. Считать P@10 и nDCG — после проверки
человеком.

## Что дальше

1. Человек проверяет лист из 200 пар: заполняет колонки «ВАША …» и пишет, кто проверял. Там самые спорные пары —
   на них черновик ошибается чаще всего.
2. Ещё 50–100 случайных пар из `llm_draft_labels.csv` — чтобы узнать, как часто ошибается черновик, когда модели
   согласны.
3. Проверенные пары — в `data/gold/gold_pairs.csv` (A1), затем метрики A2.

Повторить или продолжить (готовое пропускается):

```bash
cd backend
LLM_PROVIDER=gateway LLM_TIMEOUT=300 caffeinate -i python -m scripts.overnight_labels --extend-demo
python -m scripts.overnight_labels --compile-only     # пересобрать файлы без вызовов
```
