## Топ-10 находок (по влиянию на кейс)

1. **С ключом агент фактически отвечал правилами.** GLM тратит 8–9 тыс. токенов на «размышления», а агент давал
   ему 1800 — ответ всегда пустой. Исправлено в ветке `fix/c-reasoning-room`: у каждой модели запас токенов.
2. **Ответ GLM — 60–80 секунд, а таймаут по умолчанию — 60.** Половина ответов оборвётся. Нужно поставить
   `LLM_TIMEOUT=180` в `.env` или сделать DeepSeek первой моделью ответа.
3. **Позиция банка приклеивается к не связанным новостям:** 58 из 69 ответов, из них 35 — к новостям вообще не про
   экономику (сделка в ИИ, происшествие в Шымкенте). Чинят B1 и C1.
4. **Агент выбрасывает позицию банка, которую дала модель.** Модели пишут ссылку `ALFA-…#8`, агент ждёт
   `bank:ALFA-…#8`. Исправление маленькое, в C1.
5. **40% утверждений модели агент отбрасывает** (454 из 1147) — пользователь видит текст правил вместо текста
   модели. Частично из-за находки 4.
6. **В 47 из 70 ответов нет ни одного действия** («что делать» — один из 6 обязательных вопросов). Нужно честное
   «влияние слабое, действий не нужно» (C2).
7. **Роли не меняют действия:** для финансового директора, собственника и казначея списки одинаковые (C3).
8. **База может блокироваться, пока модель думает:** в прогоне 4 параллельных запуска падали с «database is
   locked». На показе это, вероятно, ошибка при одновременных запросах нескольких членов жюри — проверить.
9. **Модели-разметчики хорошо согласны** (каппа 0,78, «значимо / не значимо» совпадает в 94%). Первый сигнал: наша
   модель ставит наверх в 3,4 раза больше значимых новостей, чем случайный выбор. Это ещё не эталон.
10. **Половина чисел, которые Qwen3-VL выписала из аналитики банка, не находится в распознанном тексте страницы.**
    Либо распознавание текста не видит графики, либо модель ошибается — без человека не различить. 50 контрольных
    вопросов проверены и годятся для B4.

Все цифры по агенту — [BASELINE.md](BASELINE.md).

## Что сделать человеку

1. **Проверить лист из 200 пар** (`review_200_LLM_draft_not_gold.csv`, открывается в Excel). Там пары, где модели
   разошлись сильнее всего. Заполнить колонки «ВАША важность / влияние / срочность» и «Кто проверял». Примерно
   2–3 часа. Потом ещё 50–100 случайных пар из `llm_draft_labels.csv`.
2. **Поставить в `.env` `LLM_TIMEOUT=180`.** Без этого ответы GLM обрываются.
3. **Создать и слить PR** (ссылки ниже). Начать с `fix/c-reasoning-room`: без него модели отвечают пусто.

## Ветки и готовые описания PR

Во всех ветках этапов есть одинаковый файл `backend/scripts/batch_runner.py` — общий запускатель платных вызовов.
Поэтому ветки сливаются в любом порядке без конфликтов.

### 1. `fix/c-reasoning-room` — https://github.com/denisfominov/hakaton/pull/new/fix/c-reasoning-room

**Что сделано:** у каждой «думающей» модели теперь свой запас токенов на рассуждение (`llm_router.REASONING_ROOM`):
GLM +14 000, Qwen3.6 +7 000, DeepSeek +4 000, Kimi +10 000. Клиент модели просит у шлюза «размер ответа + запас».
Добавлены общий запускатель платных вызовов и скрипт замера.

**Зачем:** при старых настройках ответ агента от GLM всегда был пустым — модель тратила весь лимит на рассуждение,
и агент отвечал правилами. Замер на настоящем запросе агента стоил 4,26 ₽.

**Как проверить:** `cd backend && python -m pytest -q` (новый тест `tests/test_reasoning_room.py`). Результаты
замера — в docs/GATEWAY_QUESTIONS.md, раздел «Запас на рассуждение». Совет: поставить `LLM_TIMEOUT=180` в `.env`.

### 2. `feature/a-llm-draft-labels` — https://github.com/denisfominov/hakaton/pull/new/feature/a-llm-draft-labels

**Что сделано:** скрипт черновой разметки пар «компания × новость» (задача A1). GLM и DeepSeek размечают
независимо, Qwen3.6 решает расхождения. Описание и цифры согласия — docs/a/LLM_DRAFT_LABELS.md, строка в
THIRD_PARTY_NOTICES.

**Зачем:** чтобы человек начал не с пустого листа, а проверял 200 самых спорных пар. Метки — черновик, на них не
обучаем, в git не попадают.

**Как проверить:** прочитать docs/a/LLM_DRAFT_LABELS.md; файл `backend/data/overnight/d/review_200_LLM_draft_not_gold.csv`
открывается в Excel.

### 3. `feature/c-model-comparison` — https://github.com/denisfominov/hakaton/pull/new/feature/c-model-comparison

**Что сделано:** сравнение 5 моделей на 30 настоящих запросах агента (разные клиенты и роли). Проверки без
модели-судьи: формат, выдуманные числа и имена, время, цена. Итог и рекомендуемый маршрут моделей по задачам —
docs/MODEL_COMPARISON.md.

**Зачем:** выбрать модели для показа: что быстрее, дешевле и меньше выдумывает.

**Как проверить:** прочитать docs/MODEL_COMPARISON.md. Маршрут в коде не меняли — это решение команды, после C1
сравнение повторить.

### 4. `feature/c-baseline-stress` — https://github.com/denisfominov/hakaton/pull/new/feature/c-baseline-stress

**Что сделано:** стресс-прогон агента с настоящей моделью: 20 новых новостей × 3 клиента кейса плюс сравнение
ролей. Ничего не исправляли — цифры и список ошибок по влиянию на кейс в docs/BASELINE.md.

**Зачем:** точка отсчёта перед B1, C1, C2, C3 — после них повторить и сравнить.

**Как проверить:** прочитать docs/BASELINE.md.

### 5. `feature/b-bank-claims` — https://github.com/denisfominov/hakaton/pull/new/feature/b-bank-claims

**Что сделано:** тезисы и числа со всех 64 страниц аналитики банка (Qwen3-VL) и 50 контрольных вопросов с
ожидаемой страницей. Каждый вопрос проверен: его ответ есть в тексте страницы. Описание — docs/b/BANK_CLAIMS.md.

**Зачем:** сырьё для B1 (связь фрагмента банка с событием) и B4 (контрольные вопросы поиска).

**Как проверить:** прочитать docs/b/BANK_CLAIMS.md; файлы — `backend/data/overnight/f/` (не в git).

### 6. `docs/overnight-report` — https://github.com/denisfominov/hakaton/pull/new/docs/overnight-report

**Что сделано:** этот отчёт, записка о состоянии и продолжении (docs/OVERNIGHT_STATUS.md), запись в CHANGELOG
сразу за все ночные PR.

**Зачем:** одна запись в CHANGELOG вместо пяти — чтобы ветки не конфликтовали в одном файле.

**Как проверить:** прочитать docs/OVERNIGHT_REPORT.md.
