# Изменения

Каждый промпт — новая версия: ветка `prompt-N` (ранние версии — `первый-промпт`, `второй-промпт`) и тег `vN`.
Новые записи добавляются сверху.

## v4 — 2026-10-19

Ветка `prompt-4`, база — версия 2 (`dev`). Изменения относительно v2 (v3 в репозитории без кода):

**Профиль компании**
- Поля разделов «Что продаёт и кому», «Цели и риски», «Как искать новости» — выпадающие списки: сначала варианты,
  типичные для отрасли, затем общие и введённые в других профилях; своё значение добавляется через Enter.
- 13 отраслевых шаблонов (`backend/app/catalog.py`), `GET /api/profile-options`.
- Автозаполнение новой компании по отрасли и описанию: `POST /api/profiles/suggest`, флаг `autofilled`
  до подтверждения пользователем; кнопка «Дополнить по отрасли» для пустых полей.

**Данные**
- Компания ООО «К2 Тул» (поставщик станков, сварочных роботов и инструмента).
- 7 реальных публикаций за 24.07–12.10.2026 (k01–k07), подборка — 29 публикаций.
- Период 90 дней в обзоре и ленте, динамика за 90 дней — по неделям (`trend_step`).

**Аналитика**
- Своя модель на оценках пользователя (`backend/app/model.py`): таблицы `feedback`, `models`, `settings`;
  `POST /api/events/{id}/feedback`, `GET /api/model`, `POST /api/model/train`, `PUT /api/model/settings`.
  Логистическая регрессия «значимо ли для компании» сдвигает релевантность (вес до 50%, растёт с числом оценок),
  вторая модель подсказывает тип влияния, когда правила его не нашли. Явная оценка события учитывается сразу.
- Новые правила: `clients_capex` (инвестиции клиентов), `localization` (давление локализации на импортёра),
  поддержка покупателей оборудования как спрос для поставщика.
- Словари: станки, металлообработка, сварка, роботизация; регионы Дальнего Востока и Урала; меры поддержки
  «компенсировать / возмещение затрат»; сигналы `invest_down` / `invest_up`, `localization`.

**Интерфейс**
- Блок «Оцените разбор» на странице события.
- Бейдж «Аналитика» открывает панель с устройством аналитики и состоянием модели.
- Modal рендерится через портал (окно из шапки больше не обрезается).

**Исправления**
- Ошибка 500 при параллельных запросах: стеммер snowball теперь свой в каждом потоке (и с кэшем),
  очистка кэша анализа не падает, если ключ уже удалил соседний поток.

**Тесты**: 57 → 75.
