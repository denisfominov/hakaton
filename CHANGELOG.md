# Изменения

Каждый промпт — новая версия и тег `vN`. До v7 — ветки `prompt-N` (ранние — `первый-промпт`, `второй-промпт`),
с v8 — ветка фичи от `main` и пулл-реквест в `main`.
Новые записи добавляются сверху.

## v8 — 2026-10-19

Ветка `docker` (от `main`), в `main` — через пулл-реквест. Изменения относительно v7:

- `Dockerfile`: двухэтапная сборка — `node:20-alpine` собирает фронтенд, `python:3.12-slim` + uv ставит зависимости
  backend; один контейнер на порту 8000, база в томе `/data` (`DB_PATH=/data/alpha.db`), пользователь без root,
  `HEALTHCHECK` по `/api/health`.
- `.dockerignore`: без `node_modules`, `.venv`, баз, `.env`, `.git`, кэшей.
- Backend отдаёт собранный фронтенд при заданном `FRONTEND_DIST` (`main.mount_frontend`): файлы сборки,
  остальные пути — `index.html` для маршрутов React, выход за пределы папки сборки запрещён, `/api/*` — 404.
- CLAUDE.md: рабочий процесс через `main` → ветка фичи → пулл-реквест → слияние → тег; ветки `prompt-N` больше не
  создаются, история старых веток — для справки.
- Тесты: 122 → 123 (отдача фронтенда).

## v7 — 2026-10-19

Ветка `prompt-7`, база — версия 6 (`prompt-6`). Реализованы предложения 1, 3, 7, 10. Изменения относительно v6:

**Поиск названий (ner.py)**
- Леммы pymorphy3 и NER natasha сохраняются в признаках события (`nlp.lemmas`, `nlp.entities`).
- `matching.name_match`: аббревиатуры — заглавными, однозначные имена — совпадение лемм подряд, обычные слова
  и география — только внутри организации по NER. Без библиотек — поиск по корням, как раньше.
- `matching.is_name_term`: какие термины профиля считать названиями (конкуренты-одно слово, имена до 3 слов,
  аббревиатуры), остальное — темы, ищутся по корням.

**Портфель**
- `GET /api/portfolio?days=`: по каждой компании — индекс внимания, критические риски, риски, возможности, срочное,
  главное событие, активные сюжеты, тепловая карта по категориям. Страница `/portfolio`.

**Сюжеты (threads.py)**
- Связь групп публикаций за 60 дней: TF-IDF по леммам ≥ 0,38; или ≥ 0,22 при общей редкой организации или двух
  редких словах в заголовках; защита от «сцепок». Название — согласованная фраза из общих слов.
- Колонка `events.thread_id`, таблица `threads`; сюжет на карточке, хронология в разборе, блок на обзоре.

**Скорость (store.py, jobs.py)**
- Таблица `analysis_snapshots` (zlib-JSON на компанию), ключ — отпечаток профиля, данных, меток модели и кода.
- Фоновый поток пересчитывает после изменений и раз в час; устаревший снимок отдаётся сразу.
- Лента постранично (`limit`=30 по умолчанию, `offset`), «Показать ещё» во фронтенде. SQLite в режиме WAL.

**Тесты**: 103 → 122 (NER, снимки, пагинация, сюжеты, портфель).

## v6 — 2026-10-19

Ветка `prompt-6`, база — версия 5 (`prompt-5`). Изменения относительно v5:

**Компании**
- `lookup.collect`: ЕГРЮЛ -> параллельно Checko (`portals.checko`), «За честный бизнес» (`portals.zchb`), сайт компании
  (главная + до двух страниц «О компании»/«Продукция»), Википедия (`portals.wikipedia`); сайт с портала догружается.
  Журнал по каждому источнику (`sources_log`) — в ответе и в профиле.
- `company.build`: отрасль голосованием (ОКВЭД ×2, у холдингов ×0,5; Википедия ×2; сайт ×1,5), название из сайта /
  Википедии, описание с видом деятельности, выручкой, численностью и реквизитами, подотрасли из родственных ОКВЭД,
  продукты из структуры выручки.
- `catalog.suggest`: тексты разделены на надёжные (описание, заголовки, Википедия, ОКВЭД) и длинный текст сайта
  (только своя отрасль и ≥2 упоминаний).
- Таблица `custom_options`: свои значения пользователей становятся вариантами для всех компаний.
- Все списки профиля и вариантов — по алфавиту (`catalog.sort_values`, фронтенд — `Intl.Collator("ru")`).
- Свой разбор robots.txt по правилам Google (стандартный `urllib.robotparser` терял правила после пустой строки).

**Новости и достоверность**
- `data/sources.json`: 18 RSS (15 российских, 3 зарубежных русскоязычных), параллельная загрузка, зарубежные — не больше
  10% новых (`pipeline.FOREIGN_SHARE`), итоги загрузки — `settings.last_live`.
- `data/outlets.json` + `outlets.py`: реестр изданий и достоверность события (репутация × 70 + независимые издания
  +12/+20/+25 + официальный +15 − подозрительный текст 30). Карточки, разбор, фильтр `min_verification`, сортировка
  `verification`, `GET /api/outlets`.

**Интерфейс**
- Меню «Новости»: что в ленте, когда загружено, число компаний и изданий (RU/зарубежные), окно «Источники и их репутация».
- Убран выбор компании в шапке; логотип ведёт на страницу «О сервисе» (`/about`), справка с обзора перенесена туда.
- Блок «Достоверность» в разборе события, значок достоверности на карточках, фильтр в ленте.
- Журнал источников в баннере автозаполненного профиля.

**Тесты**: 91 → 103, сеть в тестах отключена по умолчанию (`conftest.no_network`).

## v5 — 2026-10-19

Ветка `prompt-5`, база — версия 4 (`prompt-4-(почка-от-prompt-2)`). Изменения относительно v4:

**Своя модель: обучение без оценок пользователя**
- Разметка по реакции рынка (`backend/app/market.py`): отклонение акции от IMOEX за 2 торговых дня после новости,
  z-оценка относительно обычной волатильности за 60 дней. |z| ≥ 2 — «значимо» (если правила видят хоть какую-то
  связь), |z| < 0,7 — «рынок не заметил» (только для новостей с релевантностью по правилам до 40), остальное не
  используется. Несколько новостей в один день — вес метки делится.
- История для разметки: `data/history/key_rate_decisions.json` (37 решений ЦБ с 2020 года по таблице cbr.ru),
  снимок котировок `data/market/prices.json` (Мосбиржа ISS, с 2019-10). Скрипты `scripts/build_market_data.py`
  и `scripts/import_history.py` (свой архив CSV/JSON).
- Модель: метки пользователя (вес 1) + рыночные (0,3 / 0,15); голос модели от рыночных меток — до 25%, при
  точности хуже правил — вдвое меньше. Тип влияния — только по оценкам людей. Тип источника убран из признаков.
- В профиле поле `ticker`; таблицы `prices`, `auto_labels`; `POST /api/model/market`; реакция рынка в разборе события.

**Действия**
- У каждого действия `why`, `if_done`, `if_ignored` (50 действий в правилах, схема LLM, таблица `actions`,
  форма и карточки плана).

**Компании**
- Страница «Выбор компании» (`/companies`), первая в меню. Удаление встроенных компаний с восстановлением
  (`POST /api/profiles/restore-presets`), последнюю компанию удалить нельзя.
- `POST /api/companies/lookup`: ИНН (контрольная сумма, ЕГРЮЛ или DaData с ОКВЭД) и сайт (title, description,
  заголовки, текст; запросы во внутреннюю сеть запрещены) -> автозаполненный профиль. Поля профиля `inn`, `website`.
- Автозаполнение: отрасль — по частоте корней в тексте и по названию («Сбербанк» -> банки); по тексту сайта
  ищутся только продукты, клиенты, регионы, подотрасли и ключевые слова.

**Обзор**
- Динамика повестки: у каждого столбца список событий; подсказка с заголовками, клик — список со ссылками.
- Справка «что это, зачем, как пользоваться, куда смотреть».

**Тесты**: 75 → 91.

## v4 — 2026-10-19

Ветка `prompt-4`, база — версия 2 (`dev`). Изменения относительно v2 (v3 в репозитории без кода):

**Профиль компании**
- Поля разделов «Что продаёт и кому», «Цели и риски», «Как искать новости» — выпадающие списки: сначала варианты,
  типичные для отрасли, затем общие и введённые в других профилях; своё значение добавляется через Enter.
- 13 отраслевых шаблонов (`backend/app/catalog.py`), `GET /api/profile-options`.
- Автозаполнение новой компании по отрасли и описанию: `POST /api/profiles/suggest`, флаг `autofilled`
  до подтверждения пользователем; кнопка «Дополнить по отрасли» для пустых полей.

**Данные**
- Компания ООО «К2 Тул» (поставщик станков, сварочных роботов и инструмента).
- 7 реальных публикаций за 24.07–12.10.2026 (k01–k07), подборка — 29 публикаций.
- Период 90 дней в обзоре и ленте, динамика за 90 дней — по неделям (`trend_step`).

**Аналитика**
- Своя модель на оценках пользователя (`backend/app/model.py`): таблицы `feedback`, `models`, `settings`;
  `POST /api/events/{id}/feedback`, `GET /api/model`, `POST /api/model/train`, `PUT /api/model/settings`.
  Логистическая регрессия «значимо ли для компании» сдвигает релевантность (вес до 50%, растёт с числом оценок),
  вторая модель подсказывает тип влияния, когда правила его не нашли. Явная оценка события учитывается сразу.
- Новые правила: `clients_capex` (инвестиции клиентов), `localization` (давление локализации на импортёра),
  поддержка покупателей оборудования как спрос для поставщика.
- Словари: станки, металлообработка, сварка, роботизация; регионы Дальнего Востока и Урала; меры поддержки
  «компенсировать / возмещение затрат»; сигналы `invest_down` / `invest_up`, `localization`.

**Интерфейс**
- Блок «Оцените разбор» на странице события.
- Бейдж «Аналитика» открывает панель с устройством аналитики и состоянием модели.
- Modal рендерится через портал (окно из шапки больше не обрезается).

**Исправления**
- Ошибка 500 при параллельных запросах: стеммер snowball теперь свой в каждом потоке (и с кэшем),
  очистка кэша анализа не падает, если ключ уже удалил соседний поток.

**Тесты**: 57 → 75.
