# hakaton — Alpha Intelligence

Новостная аналитика для принятия бизнес-решений. Трек «Новостная аналитика», направление КИБ.

Сервис берёт поток новостей, сопоставляет каждую новость с профилем конкретной компании и отвечает руководителю на вопросы:
что произошло, почему это важно именно для нас, какие риски и возможности, насколько срочно и что делать.
Это не агрегатор: главное — персональная оценка, объяснение «почему» и конкретные действия.

## Что умеет MVP

- **Обзор для руководителя** — важные события, критические риски, возможности, срочное, динамика повестки по дням,
  значимые темы, решения в работе. Фильтры по периоду, категории, важности и типу влияния.
- **Профиль компании** — отрасль, регионы, продукты, клиенты, поставщики, конкуренты, цели, приоритеты, риски,
  инвестпланы, ключевые слова. Три синтетических демо-профиля, можно создать свой. Профиль реально меняет оценки.
- **Лента событий** — карточки бизнес-событий: релевантность, влияние, уверенность, срочность, статус проверки фактов,
  тип влияния (риск / возможность). Поиск, фильтры, сортировка, избранное, склейка дублей в одну карточку.
- **Разбор события** — 10 блоков: суть, связь с компанией, причинно-следственная цепочка, риски, возможности,
  горизонт, срочность, действия, что отслеживать, обоснование (источники, допущения, пробелы в данных).
- **Прозрачный рейтинг 0–100** — видно, из каких факторов сложился балл и какие его снизили.
  Релевантность, влияние, срочность и уверенность считаются отдельно.
- **Сравнение** — та же новость глазами других компаний.
- **Панель решений** — план действий со статусами (новое / в работе / выполнено), сроками, ответственными,
  комментариями и историей изменений.
- **Данные** — встроенный демо-набор (22 синтетических события) и реальные RSS (Банк России, Интерфакс, РБК, Коммерсантъ).
  Режим данных всегда виден в шапке, демо-события помечены.
- **LLM (необязательно)** — Claude переписывает разбор по структурированной схеме, факты сверяются с текстом источника.
  Без ключа всё работает на правилах.

## Быстрый старт

Нужны Python 3.11+ и Node.js 20+.

### Backend

```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --port 8000 --reload
```

При первом запуске создаётся `backend/alpha.db`, загружаются демо-профили и демо-новости.
Документация API: http://127.0.0.1:8000/docs

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Открыть http://127.0.0.1:5173. Vite проксирует `/api` на backend (порт 8000).

### Тесты

```bash
cd backend
python -m pytest -q
```

41 тест: NLP-словари, скоринг и персонализация на демо-сценариях, дедупликация, пост-проверка ответа LLM, API.
Тесты работают без интернета и без ключей.

## Настройка

Все настройки — переменные окружения, пример в [.env.example](.env.example). Скопируйте его в `.env`.

### Подключение LLM

1. Получите ключ Anthropic API.
2. В `.env`: `ANTHROPIC_API_KEY=...` (модель по умолчанию `claude-opus-5-5`, можно поменять через `LLM_MODEL`).
3. Перезапустите backend. В шапке появится «Правила + LLM», на странице события станет активна кнопка
   «Углублённый анализ LLM».

LLM вызывается только по кнопке (чтобы не тратить деньги на всю ленту). Результат кэшируется в БД для пары
«событие + профиль» и помечается устаревшим, если профиль поменяли. Ошибки модели (лимиты, сеть, невалидный ответ)
показываются в интерфейсе, а пользователь остаётся с анализом на правилах.

### Источники новостей

Список RSS — в [backend/data/sources.json](backend/data/sources.json): `name`, `url`, `reliability` (0–1, влияет на
уверенность), `official`, `enabled`. Загрузка — кнопка «Обновить ленту → Загрузить реальные новости» или
`POST /api/refresh {"mode": "live"}`.

Правила сбора: только публичные RSS, свой User-Agent, таймаут, не больше одного повтора и только при сетевой ошибке
или 5xx (на 403/404 не повторяем). Ошибка источника не ломает остальные, всё пишется в `fetch_log`.

### Новости и аналитика Альфа-Банка

Есть заготовка коннектора `AlfaBankSource` в [backend/app/sources.py](backend/app/sources.py). Доступа к API у нас нет,
поэтому **интеграция не работает и не проверялась**. Формат ответа в коде — наше предположение. Если организаторы дадут
доступ, нужно заполнить `ALFA_NEWS_API_URL` и `ALFA_NEWS_API_TOKEN` и поправить разбор ответа в `fetch()`.
Сейчас в интерфейсе и в `/api/status` источник честно помечен как неподключённый.

## Как это работает (кратко)

```
RSS / демо / (Альфа) -> нормализация -> склейка дублей (TF-IDF) -> сущности, регионы, отрасли, сигналы
   -> сопоставление с профилем -> каналы влияния (правила) -> баллы -> разбор + действия -> [LLM по кнопке]
```

Подробно — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Итоговый приоритет:

```
приоритет = 0,45 × релевантность + 0,25 × влияние + 0,20 × срочность + 0,10 × новизна
```

Это экспертная шкала для сортировки, а не вероятность убытка. Каждое слагаемое раскладывается на факторы в интерфейсе.

## Ограничения MVP

- Нет пользователей и авторизации. Профили, избранное и действия хранятся в локальной SQLite на сервере.
- Анализ на правилах опирается на словари и шаблоны. Он хорошо работает на типовых формулировках
  (рост цен, ограничения экспорта, ставка, требования регулятора), но может пропустить нестандартные.
  Денежный эффект не считается: в профиле нет долей закупок и продаж.
- Демо-набор синтетический: компании, события и источники вымышлены, ссылок на оригиналы нет.
  Даты демо-событий пересчитываются от момента запуска, чтобы работали фильтры по периоду.
- Живые RSS — это общий новостной поток, большая часть новостей нерелевантна (и получает низкий балл — так и задумано).
- Интеграция с Альфа-Банком — только каркас.
- LLM-режим проверен только на уровне кода и пост-проверки ответа (unit-тесты без сети). Реальные вызовы API в рамках
  хакатона не запускались, потому что не было ключа.
- Склейка дублей — по TF-IDF с порогом. Близкие, но разные события иногда могут склеиться.
