Новостная аналитика для принятия бизнес-решений. Трек «Новостная аналитика», направление КИБ.

Сервис берёт поток новостей, сопоставляет каждую новость с профилем конкретной компании и отвечает руководителю на вопросы:
что произошло, почему это важно именно для нас, какие риски и возможности, насколько срочно и что делать.
Это не агрегатор: главное — персональная оценка, объяснение «почему» и конкретные действия.

## Что умеет MVP

- **Обзор для руководителя** — важные события, критические риски, возможности, срочное, динамика повестки по дням,
  значимые темы, решения в работе. Фильтры по периоду, категории, важности и типу влияния.
- **Профиль компании** — отрасль, регионы, продукты, клиенты, поставщики, конкуренты, цели, приоритеты, риски,
  инвестпланы, ключевые слова, другие названия компании. Значения выбираются из списков (типичные для отрасли — первыми)
  или вводятся свои. Встроены шесть реальных компаний (Северсталь, X5, Сбербанк, ПИК, Аэрофлот, К2 Тул), профили
  составлены по открытым источникам. Новую компанию сервис заполняет сам по отрасли и описанию, пользователь
  правит. Профиль реально меняет оценки.
- **Лента событий** — карточки бизнес-событий: релевантность, влияние, уверенность, срочность, статус проверки фактов,
  тип влияния (риск / возможность). Поиск, фильтры, сортировка, избранное, склейка дублей в одну карточку.
- **Разбор события** — 10 блоков: суть, связь с компанией, причинно-следственная цепочка, риски, возможности,
  горизонт, срочность, действия, что отслеживать, обоснование (источники, допущения, пробелы в данных).
- **Прозрачный рейтинг 0–100** — видно, из каких факторов сложился балл и какие его снизили.
  Релевантность, влияние, срочность и уверенность считаются отдельно.
- **Сравнение** — та же новость глазами других компаний.
- **Своя модель** — учится на оценках пользователя («относится / не относится», риск / возможность, важность)
  и поправляет релевантность похожих новостей. Состояние и точность — по клику на бейдж «Аналитика».
- **Панель решений** — план действий со статусами (новое / в работе / выполнено), сроками, ответственными,
  комментариями и историей изменений.
- **Данные** — подборка из 29 реальных публикаций (Reuters, Интерфакс, Коммерсантъ, Ведомости, РГ, Банк России и др.)
  со ссылками на оригиналы и кратким пересказом фактов за 24 июля — 16 октября 2026 (фильтр «90 дней»), плюс свежие RSS (Банк России, Интерфакс, РБК, Коммерсантъ).
  Синтетический набор оставлен для тестов (`DATASET=synthetic`). Режим данных всегда виден в шапке.
  Список публикаций — в [docs/DATA.md](docs/DATA.md).
- **LLM (необязательно)** — Claude переписывает разбор по структурированной схеме, факты сверяются с текстом источника.
  Без ключа всё работает на правилах.

## Быстрый старт

Нужны Python 3.12 (работает и 3.11) и Node.js 20+. Удобнее всего через [uv](https://docs.astral.sh/uv/):
`uv venv --python 3.12 && uv pip install -r requirements.txt`. Ниже — вариант со стандартным venv.

### Backend

```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --port 8000 --reload
```

При первом запуске создаётся `backend/alpha.db`, загружаются профили шести компаний и подборка новостей.
Документация API: http://127.0.0.1:8000/docs

Если база осталась от старой версии с вымышленными компаниями, при запуске их события и встроенные профили удаляются
автоматически (созданные вами профили и план действий сохраняются). Для полностью чистого старта удалите `backend/alpha.db`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Открыть http://127.0.0.1:5173. Vite проксирует `/api` на backend (порт 8000).

### Тесты

```bash
cd backend
python -m pytest -q
```

75 тестов: логика на синтетическом наборе (там заранее известен правильный вывод: NLP, скоринг, персонализация,
дубли, пост-проверка LLM, API), справочники и автозаполнение профиля, обучение своей модели на оценках
и проверки реальной подборки (ссылки, даты, склейка дублей, ключевые выводы по каждой компании, включая К2 Тул).
Работают без интернета и без ключей.

## Настройка

Все настройки — переменные окружения, пример в [.env.example](.env.example). Скопируйте его в `.env`.

### Подключение LLM

1. Получите ключ Anthropic API.
2. В `.env`: `ANTHROPIC_API_KEY=...` (модель по умолчанию `claude-opus-5-5`, можно поменять через `LLM_MODEL`).
3. Перезапустите backend. В шапке появится «Правила + LLM», на странице события станет активна кнопка
   «Углублённый анализ LLM».

LLM вызывается только по кнопке (чтобы не тратить деньги на всю ленту). Результат кэшируется в БД для пары
«событие + профиль» и помечается устаревшим, если профиль поменяли. Ошибки модели (лимиты, сеть, невалидный ответ)
показываются в интерфейсе, а пользователь остаётся с анализом на правилах.

### Источники новостей

Встроенная подборка — [backend/data/real/news.json](backend/data/real/news.json), как её пополнять — в
[docs/DATA.md](docs/DATA.md).

Список RSS — в [backend/data/sources.json](backend/data/sources.json): `name`, `url`, `reliability` (0–1, влияет на
уверенность), `official`, `enabled`. Загрузка — кнопка «Обновить ленту → Загрузить свежие новости из RSS» или
`POST /api/refresh {"mode": "live"}`. В ленте по умолчанию включён фильтр «Только значимые для компании»: он скрывает
новости с релевантностью ниже 20 — в общих RSS их большинство.

Правила сбора: только публичные RSS, свой User-Agent, таймаут, не больше одного повтора и только при сетевой ошибке
или 5xx (на 403/404 не повторяем). Ошибка источника не ломает остальные, всё пишется в `fetch_log`.

### Новости и аналитика Альфа-Банка

Есть заготовка коннектора `AlfaBankSource` в [backend/app/sources.py](backend/app/sources.py). Доступа к API у нас нет,
поэтому **интеграция не работает и не проверялась**. Формат ответа в коде — наше предположение. Если организаторы дадут
доступ, нужно заполнить `ALFA_NEWS_API_URL` и `ALFA_NEWS_API_TOKEN` и поправить разбор ответа в `fetch()`.
Сейчас в интерфейсе и в `/api/status` источник честно помечен как неподключённый.

## Как это работает (кратко)

```
подборка / RSS / (Альфа) -> нормализация -> склейка дублей (TF-IDF + общие числа) -> сущности, регионы, отрасли, сигналы
   -> сопоставление с профилем -> каналы влияния (правила) -> баллы -> разбор + действия -> [LLM по кнопке]
```

Подробно — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Итоговый приоритет:

```
приоритет = 0,45 × релевантность + 0,25 × влияние + 0,20 × срочность + 0,10 × новизна
```

Это экспертная шкала для сортировки, а не вероятность убытка. Каждое слагаемое раскладывается на факторы в интерфейсе.

## Ограничения MVP

Подробно, с примерами ошибок на реальных данных, — в [docs/REVIEW.md](docs/REVIEW.md). Коротко:

- Подборка реальных новостей — снимок за 24.07–16.10.2026 (29 публикаций). Со временем она стареет:
  приоритет учитывает свежесть, свежие события нужно подгружать из RSS или добавлять в подборку.
- Анализ на правилах опирается на словари корней. На реальных текстах всплыли омонимы и отрицания («Самолёт» в
  «самолётов», «сокращение программ поддержки») — найденные случаи исправлены и закреплены тестами,
  но системно это решается лемматизацией и извлечением сущностей.
- Качество не измерено на разметке: тесты проверяют логику, а не точность. Своя модель считает точность
  кросс-валидацией на оценках пользователя, но их пока нет — модель стартует пустой.
- Денежный эффект не считается: в профиле нет долей закупок, продаж и структуры долга.
- Живые RSS — общий поток на русском, большая часть нерелевантна (фильтр «Только значимые» её скрывает).
- LLM-режим проверен только на уровне кода и пост-проверки ответа (тесты без сети); реальных вызовов API не было — не было ключа.
- Интеграция с Альфа-Банком — только каркас.
- Нет пользователей и авторизации; данные — в локальной SQLite.
