# hakaton — Alpha Intelligence

Агент новостной аналитики для руководителей крупного бизнеса (выручка от 15 млрд ₽).
Кейс «Альфа Хак: Новостная аналитика», направление КИБ.

Описание — состояние ветки `main`. История изменений — только в [CHANGELOG.md](CHANGELOG.md).

> **Этот README — для команды:** как устроен проект, как мы работаем, где что лежит и что делаем дальше.
> README для жюри (назначение, запуск, переменные, сценарий проверки по формату сдачи) — задача D8a, пишем позже.

Состояние на **2026-10-21**, после PR #31. Проверено по коду и замерам из [docs/GAP_ANALYSIS.md](docs/GAP_ANALYSIS.md).

## Что это

Помощник для руководителя компании — клиента банка. Он сам собирает новости, выбирает важные для конкретной
компании, объясняет, чем каждая грозит или помогает, подкрепляет вывод аналитикой Альфа-Банка и предлагает, что
сделать. Вход — из Альфа-Бизнеса (интернет-банк для юрлиц).

## Как устроено

```
Новости (18 RSS-лент) ─┐
Данные клиентов (CSV)  ├─► Бэкенд (Python, FastAPI) ─► Агент ─► Ответ ─► Фронтенд (React)
Аналитика банка (PDF) ─┘        база SQLite              │
                                                         └─► LLM через шлюз организаторов (по желанию)
```

- **Бэкенд** (серверная часть) — [backend/app/](backend/app/): сбор новостей ([sources.py](backend/app/sources.py)),
  склейка дублей ([dedup.py](backend/app/dedup.py)), профиль компании ([clients.py](backend/app/clients.py),
  [company_features.py](backend/app/company_features.py)), отбор ([scoring.py](backend/app/scoring.py)), поиск по
  аналитике банка ([bank_rag.py](backend/app/bank_rag.py); RAG — поиск нужных кусков документов перед ответом).
- **Агент** — своя логика, без фреймворков: [agent.py](backend/app/agent.py), [agent_tools.py](backend/app/agent_tools.py).
  Строит план, вызывает 8 инструментов, проверяет себя, собирает ответ из 6 блоков с источником у каждого
  утверждения.
- **LLM** (большая языковая модель) — не обязательна: без неё работают правила. С ней — только 6
  разрешённых моделей через [llm_client.py](backend/app/llm_client.py); бюджет 500 ₽ в день на всю команду.
- **Фронтенд** (то, что видно в браузере) — [frontend/src/pages/](frontend/src/pages/): лента, событие, компании,
  портфель, решения, банк, макет Альфа-Бизнеса.
- **Скрипты** — [backend/scripts/](backend/scripts/): разметка, проверка показа
  (`demo_check`), платная очередь (`daily_paid`).
- **Тесты** — [backend/tests/](backend/tests/), 269 проходят (2026-10-21).

## Как запустить

```bash
docker compose up --build
```

Открыть http://localhost:8000 (API — `/api`, описание API — `/docs`). Без файла `.env` всё работает без LLM.
Запуск для разработки, тесты и настройки — в [CLAUDE.md](CLAUDE.md), раздел «Run».

Не в git (лежат только локально): PDF кейса и данные клиентов `df_*_hack.csv` в корне, PDF аналитики банка,
веса моделей, папка лекций, `.env`.

## Как мы работаем

- **Двое, две зоны.** Ч1 — «агент и интерпретация», Ч2 — «данные, поиск и качество». Чьи какие файлы —
  [docs/TASKS.md](docs/TASKS.md).
- **Одна задача = одна ветка = один PR.** Ветка — отдельная копия кода под задачу; PR — заявка влить её в
  основную версию `main`. PR создаёт и сливает человек на GitHub. Открытых PR — не больше двух на команду.
- **У каждой задачи — ID** (A8, C17, …) в [docs/TASK_REGISTER.md](docs/TASK_REGISTER.md). Новая задача — строкой в
  [docs/TASK_INBOX.md](docs/TASK_INBOX.md).
- **Ответы организаторов главнее наших догадок:** [docs/QUESTIONS.md](docs/QUESTIONS.md) (пересказ),
  [docs/ORGANIZERS_RAW.md](docs/ORGANIZERS_RAW.md) (дословно).
- **Платные вызовы LLM** — только после согласия и оценки цены; перед ручным вызовом — сообщение в чат команды.
- **ML-задачи** (машинное обучение) — сверяем с лекциями курса: [docs/ML_LECTURES_INDEX.md](docs/ML_LECTURES_INDEX.md).
- Правила для Claude — [CLAUDE.md](CLAUDE.md).

## Текущий статус

Слито 31 PR. В реестре 80 задач: 25 сделано, 37 не начаты, остальные отложены или отброшены.

**Работает:** путь от входа в макете Альфа-Бизнеса до создания действия (`demo_check` — 6 шагов из 7, ошибок 0);
утверждений без источника — 0 из 491; враждебные новости с вредными инструкциями обезвреживаются; запрет чужих
моделей и SDK проверяется тестами.

**Главные пробелы** (подробно — [docs/GAP_ANALYSIS.md](docs/GAP_ANALYSIS.md), топ-10):

1. Позиция банка — редкая (14 ответов из 50, все про ставку); ссылки модели на банк агент выбрасывает из-за
   формата — C1b, B4.
2. README для жюри не написан — D8a.
3. Отрасль по ОКВЭД неверна у 3 из 5 демо-клиентов (оптовая торговля → «Металлургия») — A8.
4. Самопроверка агента ни разу не изменила ход работы (0 из 50) — C9.
5. Роль (финдиректор, собственник, …) не меняет советы — C3, C12.
6. С LLM ответ обрывается: модель отвечает 60–80 с, ждём 60 с — C11.
7. Нет обязательных подписей «не официальная позиция банка» и «не является инвестиционной рекомендацией» — C17.
8. Новости не собираются сами: самая свежая в базе — 2026-10-19 — B2.1.
9. Качество отбора не проверено людьми: размечено 0 из 260 строк — A1.
