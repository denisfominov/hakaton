# hakaton — Alpha Intelligence

Агент новостной аналитики для руководителей крупного бизнеса (выручка от 15 млрд ₽).
Кейс «Альфа Хак: Новостная аналитика», направление КИБ.

Описание — состояние ветки `main`. История изменений — только в [CHANGELOG.md](CHANGELOG.md).

## Состояние (2026-10-20)

**Работает без ключа и без сети:** компании из базы кейса (115 компаний сегмента, 5 демо-клиентов), вход из макета
Альфа-Бизнеса по подписанному токену с компанией и ролью, лента и ранжирование под компанию (правила + свои
ML-модели + смысловая близость e5), агент с ответом на 6 вопросов кейса и трассировкой, поиск по аналитике банка
(гибрид e5 + TF-IDF со ссылками на страницы), живые RSS (18 изданий, проверены 2026-10-20), Docker.

**Не проверено:** реальные вызовы языковых моделей — ключа шлюза у команды ещё нет; LLM-слой проверен в мок-режиме
и тестами с подменой HTTP. Кэш ответов моделей для показа без ключа пуст (`backend/data/demo_cache`).
Свои ML-модели — черновые (нет ручной разметки). Сервис нигде не развёрнут (подготовка — [docs/DEPLOY.md](docs/DEPLOY.md)).
Открытые вопросы и принятые без ответа решения — [docs/QUESTIONS.md](docs/QUESTIONS.md),
разбор пробелов по критериям кейса — [docs/GAP_ANALYSIS.md](docs/GAP_ANALYSIS.md).

## Назначение

Сервис превращает поток новостей и аналитику Альфа-Банка в персональные инсайты для ЛПР крупного бизнеса:
собственника, генерального и финансового директора, казначейства. На каждое значимое событие агент отвечает:

1. **Что произошло?** — факты из текста новости.
2. **Почему это важно для этой компании?** — связь с отраслью, продуктами банка, контрагентами, регионами.
3. **Какие последствия?** — риски и возможности, горизонт.
4. **Какие действия актуальны?** — что сделать, почему, что будет, если сделать и если не реагировать.
5. **Как это оценивает банк?** — цитаты аналитики Альфа-Банка со ссылкой на документ и страницу.
6. **На чём основан вывод?** — источники, признаки компании, ограничения данных.

Факты из новостей, позиция банка, данные о компании и выводы модели разделены и подписаны в интерфейсе и в JSON.

## Требования к окружению

- Docker 24+ с Compose v2.24+ — для запуска одной командой.
- Для разработки без Docker: Python 3.12 (`.python-version`; работает и 3.11), Node.js 20+, удобнее через
  [uv](https://docs.astral.sh/uv/).
- Интернет нужен только для свежих RSS, поиска компании по ИНН/сайту и котировок; без него сервис работает на
  встроенной подборке. LLM необязательна.

## Запуск

### Docker (рекомендуется)

```bash
cp .env.example .env          # необязательно: без .env всё работает без LLM
docker compose up --build
```

Открыть http://localhost:8000, документация API — http://localhost:8000/docs.

- Данные кейса (`df_Uid_data_hack.csv`, `df_Uid_payment_hack.csv`, `df_Fid_Uid_link_hack.csv`) берутся из корня
  репозитория (другая папка — `CASE_DATA_DIR=/path docker compose up`); нет файлов — синтетический пример
  `backend/data/clients/sample` и 6 публичных компаний.
- Аналитика банка — из `backend/data/bank` (другая папка — `BANK_DOCS_HOST_DIR=/path`). PDF кейса без текстового
  слоя: один раз распознать на машине разработчика (macOS) —
  ```bash
  cd backend
  uv run --with "pypdf[image]==5.1.0" --with ocrmac python -m scripts.ocr_bank_docs "../данные из слайда 17" --out data/bank
  ```
  или через шлюз: `python -m scripts.ocr_bank_docs <папка> --engine vl` (Qwen3-VL).
- Веса модели эмбеддингов e5 (~130 МБ, MIT) — один раз: `cd backend && python -m scripts.download_embeddings`;
  docker-compose подключает их томом. Без весов поиск и близость работают на TF-IDF. Для хостинга без томов —
  `docker build --build-arg BAKE_EMBEDDINGS=1 .` (образ больше на ~130 МБ; без весов — 933 МБ).
- Свои ML-модели (необязательно): `cd backend && python -m scripts.train_models` (~1 мин, веса не в git).

### Без ключа и со своим ключом LLM

**Без ключа** (по умолчанию, `LLM_PROVIDER=off`): разбор — правилами, своими ML-моделями и поиском по источникам,
в интерфейсе — пометка «языковая модель не подключена». Для демо-клиентов и новостей подборки агент отдаёт ответ
настоящей модели из кэша `backend/data/demo_cache`, если он там есть, с пометкой «ответ из кэша, получен ранее
моделью X, дата». Мок-режим для разработки — `LLM_PROVIDER=mock` (ответы в формате шлюза без сети, с пометкой).

**Со своим ключом** (шлюз организаторов, один ключ на команду):

```bash
cp .env.example .env
# в .env: LLM_PROVIDER=gateway, LLM_BASE_URL=<адрес из письма>, LLM_API_KEY=<ключ>, DAILY_BUDGET_RUB=100
docker compose up --build
```

- **Бюджет общий на всю команду:** 500 ₽ в день, сброс в 00:00 МСК, остаток не переносится, после дедлайна ключ
  отключается. Каждый разработчик тратит из одного лимита, поэтому сервис по умолчанию останавливается на
  `DAILY_BUDGET_RUB=100` ₽ в день (по московскому дню); договоритесь в команде, кто сколько берёт. Расход —
  страница «Расход».
- Ключ — только в `.env` (не коммитится) или в секретах хостинга; в журналы и ответы API он не попадает.
- Своя модель из списка кейса на своём сервере (Ollama/vLLM): `LLM_PROVIDER=local`, `LLM_BASE_URL=http://…/v1`.
- Заполнить кэш для показа без ключа — **один раз, когда есть ключ**:
  `cd backend && python -m scripts.warm_cache --dry-run` (план и оценка стоимости), затем
  `python -m scripts.warm_cache --events 5 --roles cfo --max-rub 60` и закоммитить `backend/data/demo_cache`.

### Локально для разработки

```bash
cd backend
uv venv --python 3.12 && source .venv/bin/activate     # Windows: .venv\Scripts\activate
uv pip install -r requirements.lock
uvicorn app.main:app --port 8000 --reload
```

```bash

```

### Тесты

```bash
cd backend
python -m pytest -q
```

205 тестов без сети и ключей (e5 в общих тестах выключена; отдельный тест проверяет e5 на скачанных весах и
пропускается, если весов нет): вход по токену и роли, бюджет по московскому дню, кэш ответов для показа без ключа,
живая загрузка RSS, контракты между частями системы (docs/CONTRACTS.md), соответствие правилам (белый список, нет SDK внешних AI), шлюз в мок-режиме (роутер,
запасная модель, бюджет, кэш, ретраи, ключ не утекает), агент (реестр со схемами и правами, план JSON, самопроверка,
противоречие «новость против банка», защита от инъекций, JSON-схема ответа), свои ML-модели (признаки, обучение,
вклад признаков, влияние на ранжирование), RAG банка и новостей, данные клиентов, NLP, скоринг, API.

## Данные кейса

- **Компании** — `df_Uid_data_hack.csv`, названий нет: подпись «Компания `U_…`: ОКВЭД, регион, выручка X млрд ₽,
  сотрудников, продукты банка». По умолчанию — 5 демо-клиентов (по одному на отрасль, крупнейший действующий клиент
  с продуктами банка; профили `case-u-…`), остальные — поиском. Публичные компании (Северсталь, X5 и др.)
  подключаются, только если данных кейса нет (`PRESET_PROFILES=1` — принудительно).
- **`REVENUE_COMPANY`** — выручка в рублях (число). Пустое или нечисловое — ноль. Сегмент КИБ — **строго больше
  15 млрд ₽** (115 компаний); в интерфейсе — млрд ₽ с одним знаком и место компании по выручке в своём классе ОКВЭД.
- **Платежи** — `df_Uid_payment_hack.csv` (`PAYER`, `BENEFICIARY`, `PAY_AMT`, `PAY_CNT`): основные поставщики и
  покупатели. **Связи** — `df_Fid_Uid_link_hack.csv`: аффилированные компании (только число общих физлиц).
- Подробно — [docs/DATA.md](docs/DATA.md), качество — [docs/DATA_QUALITY.md](docs/DATA_QUALITY.md), что храним —
  [docs/SECURITY.md](docs/SECURITY.md).

| Модуль | Что делает |
|---|---|
| `agent.py` | агент для ЛПР: план в JSON (LLM/эвристика), общий контекст, самопроверка, ответ на 6 вопросов, `agent_runs` |
| `agent_tools.py` | реестр инструментов: описание, схемы входа и выхода, права (чтение, класс данных); граф связей, RAG новостей |

| `agent_rules.py` | без LLM: участники и сроки события, вопросы для анализа, сценарии, проверки на противоречия и обоснованность, ответ на вопрос |
| `llm_client.py` | клиент шлюза: белый список, маршрут и запасная модель, кэш, бюджет, ретраи, журнал `llm_calls`, маскирование |

## Сценарий проверки

1. `docker compose up --build`, открыть http://localhost:8000 → **«Альфа-Бизнес (макет)»**: выбрать компанию кейса
   и роль (например, «Компания U_9250», «Руководитель казначейства») и нажать точку входа «Новости и аналитика для
   вашего бизнеса». Макет выпускает подписанный токен, сервис проверяет его и открывает компанию с этой ролью
   (повторно тот же токен не принимается). Счета и платежи — заглушки макета.
2. **Выбор компании** — демо-клиенты кейса и поиск по 115 компаниям сегмента (выручка больше 15 млрд ₽) с подписью
   «ОКВЭД, регион, выручка, продукты банка»; ручное добавление компании спрятано за ссылкой.
3. **Обзор и лента** показывают события, отобранные и отсортированные для этого клиента. Сменить клиента
   (например, на торговую компанию с депозитами) — лента и оценки меняются.
4. Открыть событие о ключевой ставке («Банк России … сохранить ключевую ставку на уровне 14,00%»).
   В блоке **«Инсайт для руководителя»**:
   - «Что произошло?» — факты с цифрами и ссылками на издания;
   - «Почему это важно?» — «кредиты и лизинг в банке (данные банка о клиенте)»;
   - «Последствия» — «финансовая нагрузка по долгу в ближайшие месяцы не снизится»;
   - «Действия» — с обоснованием, ответственным и сроком;
   - «Как это оценивает банк?» — цитаты аналитики банка (если материалы загружены) или честное «позиции нет»;
   - «На чём основан вывод?» — нумерованные источники и признаки компании.
   - в блоке 1 — участники, даты и отметка подтверждённости; в блоке 4 — сценарии («Ставку снизят на заседании
     23 октября…») и вопросы для анализа; в блоке 6 — проверка обоснованности и противоречий.
5. Раскрыть **«Как агент пришёл к выводу»**: план, вызовы инструментов с аргументами и итогом, самопроверка
   (при отсутствии позиции банка — повторный поиск по отрасли), время шагов.
6. Задать **уточняющий вопрос** («что делать с нашими кредитами?») — сверху появится «Ответ на вопрос»
   с относящимися к нему выводами и ссылками на источники.
7. «Создать действие» → действие попадает в «Решения» со сроком и ответственным.
8. **«Аналитика банка»** в меню — документы банка с темами и ключевыми тезисами (после загрузки PDF в
   `backend/data/bank`).
9. С LLM (`LLM_PROVIDER=gateway` или `local`): «Подготовить инсайт» → в шапке панели — модель из списка
   разрешённых; в трассировке — план, построенный моделью.
10. Сменить роль в шапке (собственник ↔ главный бухгалтер) — в инсайте меняются порядок и пометки «для вас»
    у последствий и действий и заметка для роли.

API для проверки без интерфейса:

```bash

curl -s -X POST http://localhost:8000/api/clients/U_9250/profile
curl -s -X POST http://localhost:8000/api/agent/insight -H "Content-Type: application/json" \
  -d '{"profile_id": "<id из ответа выше>", "event_id": "r21"}'

curl -s http://localhost:8000/api/agent/schema
```

## Защита данных и безопасность AI-компонентов

- **Только разрешённые модели.** Имя модели сверяется со списком кейса до запроса; SDK OpenAI и Anthropic в проекте
  нет, внешние AI-сервисы не вызываются.
- **Минимум данных в модели.** В запрос к LLM попадают только собранный агентом контекст: факты новости,
  обезличенные признаки клиента (ОКВЭД, сегмент, продукты банка, страны ВЭД) и фрагменты аналитики. Строки платежей,
  идентификаторы физлиц и контрагентов в запросы не передаются.
- **Маскирование перед внешним шлюзом:** e-mail, телефоны, ИНН/ОГРН/КПП, номера счетов заменяются метками.
- **Права инструментов.** Реестр `agent_tools.py`: у каждого инструмента — схема входа и выхода, доступ «только
  чтение» и класс данных (public / bank_internal / client_confidential). Запуск агента получает набор разрешённых
  классов (в продуктиве — по роли пользователя); инструмент вне набора отклоняется и пишется в трассировку.
  Неизвестный инструмент отклоняется, аргументы приводятся к схеме, выход проверяется. Инструментов записи,
  выполнения команд и запросов на произвольные адреса нет.
- **Недоверенные тексты.** Новости и документы банка идут в модель в тегах `<untrusted_news>`, `<untrusted_bank>`
  без угловых скобок и без строк-инструкций; промпт запрещает выполнять инструкции из них.
- **Бюджет.** Дневной лимит в ₽ (не выше 499) и в токенах проверяется до вызова; при исчерпании — правила или кэш
  с пометкой.
- **Защита от инструкций в текстах.** Новости — данные, а не команды: тексты с инструкциями для ИИ помечаются,
  в факты не попадают, уверенность снижается. Ответ модели проходит пост-проверку: факты сверяются с текстом,
  «позиция банка» без ссылки на найденный фрагмент отбрасывается.
- **Журналирование.** `llm_calls` — каждый вызов модели (модель, назначение, токены, время, ошибка; без текстов
  промптов), `agent_runs` — план, шаги, аргументы, итоги и ответ, лог `alpha.agent`. Дневной лимит токенов.
- **Секреты и данные кейса.** Ключи — только в переменных окружения; `.env`, базы, `df_*_hack.csv` и PDF не
  коммитятся и не попадают в образ (`.gitignore`, `.dockerignore`). Данные кейса подключаются томом только для
  чтения, контейнер работает не от root.
- **Вход и связь пользователя с бизнесом** подтверждает банк токеном входа; в прототипе токен смоделирован
  (HMAC, срок 5 минут, одноразовый), журнал входов — `entry_log`. Что храним и что нужно для продукта —
  [docs/SECURITY.md](docs/SECURITY.md), поток входа — [docs/ALFA_BUSINESS_ENTRY.md](docs/ALFA_BUSINESS_ENTRY.md).

## Мониторинг качества

- Оценки пользователей на каждом событии («относится / не относится», риск/возможность, важность) — учат свою
  модель. Качество — на отложенных фолдах, сгруппированных по событию: PR-AUC (главная, класс «значимо» редкий),
  ROC-AUC, precision/recall/F1, калибровка; сравнение с правилами на тех же метках (бейдж «Аналитика»).
- Рыночная разметка: реакция акций публичных компаний после новости как объективная метка значимости.
- Агент: доля ответов с позицией банка, число повторных поисков, отброшенные пост-проверкой утверждения,
  задержка и токены (`agent_runs`, `llm_calls`); расход по моделям и дням — страница «Расход».
- Свои ML-модели: `python -m scripts.evaluate_models` → docs/ML_EVALUATION.md (новые клиенты × новые новости,
  сравнение с правилами, ручная разметка по мере заполнения).
- Процесс: еженедельный разбор событий с низкой оценкой пользователей и экспертами банка → правила, словари,
  датасет для дообучения своей LLM.

## Соответствие правилам и дообучение

Только шесть разрешённых кейсом LLM через шлюз организаторов, белый список в коде, без SDK внешних AI-сервисов и
готовых агентных систем — [docs/COMPLIANCE.md](docs/COMPLIANCE.md). Модели не обучаются с нуля и не дообучаются;
идея дообучения разрешённой модели описана как предложение — [docs/FINETUNE_PROPOSAL.md](docs/FINETUNE_PROPOSAL.md).

## Ограничения

- Позиция банка — по 9 материалам приложения 2 (июль–сентябрь 2026); темы вне этих материалов агент честно
  отмечает как «позиции банка нет». Распознавание страниц — с редкими ошибками на графиках и таблицах.
- **Реальные вызовы шлюза организаторов не проверялись (нет ключа):** LLM-слой проверен в мок-режиме и тестами с
  подменой HTTP; формат API — допущение (docs/GATEWAY_QUESTIONS.md).
- Свои ML-модели — черновые: обучены на синтетике и слабой разметке правилами, ручной разметки пока нет.
- Доля рынка считается только внутри набора кейса; денежный эффект не считается; качество отбора не измерено на
  экспертной разметке.
- Подборка реальных новостей — снимок за 24.07–16.10.2026; свежие события — из RSS.
- Вход из Альфа-Бизнеса смоделирован (токен-заглушка), сессии нет; роль меняет акценты, но не права доступа; компанию можно открыть и без токена. Данные — в локальной SQLite.
- Данные кейса в pandas занимают ~370 МБ: на хостинге с 512 МБ — только публичные компании (docs/DEPLOY.md).
- Коннектор API Альфа-Банка — только каркас. Подробнее — [docs/AUDIT.md](docs/AUDIT.md), [docs/REVIEW.md](docs/REVIEW.md).
